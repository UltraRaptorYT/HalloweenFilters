# Domain Docs

Before exploring, read `GLOSSARY.md` at the repo root, or `GLOSSARY-MAP.md` if present. Read relevant decisions in `docs/adr/`; if a multi-context map exists, also check that context’s `docs/adr/`.

If these files do not exist, proceed silently. Create them only when domain modeling resolves terms or decisions.

This is a single-context repo. Domain docs belong at the root (`GLOSSARY.md`) and under `docs/adr/`.

Use glossary terms consistently. If a needed concept is missing, note it for domain modeling. If an answer conflicts with an ADR, surface the conflict explicitly.
